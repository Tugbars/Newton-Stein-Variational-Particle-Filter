System Architecture

The Pipeline

Each timestep processes a single observation — a market return yt — and produces a posterior distribution over latent log-volatility ht. The pipeline has four stages, each with a single clearly-defined responsibility. No stage duplicates another's function. No stage injects opinions about what the answer should be.

Note

95% of compute is in Newton–Stein transport. The predict step is intentionally simple — symmetric, directionless. The guide is intentionally cheap — first-order approximation. Accuracy comes from iterating on the likelihood gradient with the Hessian. The other components exist to make those iterations converge faster.

State Dynamics

p(ht | ht-1)

The state model determines how particles spread during the predict step. It answers one question: given yesterday's log-volatility ht-1, what is the distribution of possible values for today's ht? This is the proposal — it determines where particles start before Newton-Stein corrects them.

Why the State Model Matters Less Than You Think

The Stein operator does not evaluate the transition density. It only needs ∇h log p(y|h). The state model affects where particles start, not where they end up. A better proposal means faster convergence (fewer Stein steps). A worse proposal means more steps. The posterior is determined by the likelihood gradient regardless. This is why we deliberately keep the state model simple.

Gaussian AR(1)

h_t = μ + ρ(h_{t-1} - μ) + σ_z · ε ε ~ N(0, 1)
Simplest possible state dynamics. Mean-reverting, symmetric, well-understood. Exponential forgetting of shocks.
Rejected: Light tails underestimate magnitude of vol jumps. During crashes, no particles land far enough from the mean. The Stein loop can't correct if zero particles are in the right neighborhood.

Student-t AR(1)

h_t = μ + ρ(h_{t-1} - μ) + σ_z · ε ε ~ t(ν_state), ν_state ≈ 5
Same AR(1) structure, but innovations are drawn from a Student-t distribution with ν ≈ 5 degrees of freedom. Naturally places more particle mass in the tails without any binary jump/no-jump decision.
Chosen because: Heavy tails are continuous, not heuristic. No jump probability to tune, no jump scale to calibrate. Some particles naturally land far from the mean. When vol actually jumps, they're already there. When it doesn't, Newton-Stein pulls them back. One parameter (ν_state) with a clean interpretation.

Jump-Diffusion (MIM)

h_t = μ + ρ(h_{t-1} - μ) + σ_z · ε + J·Z J ~ Bernoulli(λ), Z ~ N(μ_J, σ²_J)
Gaussian AR(1) plus discrete Poisson jumps. Mixture Innovation Model — particles are occasionally perturbed by large random kicks.
Rejected: Three extra parameters (λ, μ_J, σ_J) that are heuristics. Jump probability is a guess. Jump scale is a guess. When these guesses are wrong, the jumps fight the Stein correction instead of helping it. Student-t achieves the same tail coverage with one parameter and no binary decisions.

Asymmetric ρ

ρ_effective = ρ_up if h_t > h_{t-1} = ρ_down if h_t ≤ h_{t-1} (ρ_up > ρ_down: vol rises faster than it falls)
Different persistence for upward vs downward moves. Captures the asymmetric nature of vol dynamics — fast spike, slow recovery.
Rejected: Encodes directional opinion in the proposal. The predict step should not decide whether vol is going up or down — that's the Stein loop's job after seeing the observation. Conflates shock magnitude (innovation variance) with mean-reversion speed (persistence), which are separate phenomena.

Antithetic Sampling

Regardless of the innovation distribution, particles are generated in antithetic pairs. For each random draw z, two particles are created: one at μ + ρ(h-μ) + σ·z and one at μ + ρ(h-μ) - σ·z. This guarantees that the empirical variance of the particle cloud exactly matches the theoretical variance — no sampling noise in the spread estimate.

The benefit cascades: clean particle spread → accurate bandwidth computation → well-calibrated Stein kernel → fewer wasted iterations. Variance reduction in the proposal improves efficiency of every downstream computation.

Key Insight

The Student-t predict doesn't "know" about jumps. It doesn't decide "this tick is a jump." It simply acknowledges that large innovations happen more often than Gaussian predicts. This honest statement about tail behavior — combined with antithetic variance reduction — is all the predict step needs. The Stein loop does the rest.

Observation Model

p(yt | ht)

The observation model is where accuracy lives. Unlike the state model, which only affects the proposal, the observation model directly shapes the posterior through its score function ∇h log p(y|h). Every Newton-Stein iteration evaluates this gradient. Every annealing stage scales it. If this score is biased, the entire posterior is biased. There is no downstream correction.

Critical Distinction

State model errors → particles start in the wrong place → Newton-Stein corrects.
Observation model errors → Newton-Stein converges to the wrong place → nothing corrects.

Student-t Observation

y_t | h_t ~ scale × t(ν) σ_t = exp(h_t / 2) Score: ∇_h = -1/2 + (ν+1)/2 · z²/(ν + z²) where z² = y² · exp(-h)
Returns are Student-t distributed conditional on latent vol. Heavy tails handle microstructure noise, tick quantization, and occasional extreme observations without distorting the vol estimate.
Current choice. Problem: The score has a systematic bias. For typical observations (z²≈1), the gradient pushes toward a vol level that depends on ν. Requires a manual lik_offset = 0.45 to correct. This offset interacts with ν and market conditions — another knob that can be wrong.

OCSN Observation

y_t | h_t ~ (1-α)·N(0, exp(h_t)) + α·N(0, κ²·exp(h_t)) r_n = (1-α)·φ_n / [(1-α)·φ_n + α·φ_c] Score: ∇_h = -1/2 + 1/2·[r_n·z² + (1-r_n)·z²/κ²]
Observation-Contaminated Scale Normal. Most observations (1-α) are clean Gaussian; a fraction (α) are contaminated with κ× wider variance. The filter automatically classifies each observation as clean or contaminated.
Planned upgrade because: The normal component is exactly Gaussian — zero bias by construction. No lik_offset needed. α and κ have direct market interpretations ("fraction of ticks that are garbage" and "how much wider the garbage variance is"). Outliers are ignored, not down-weighted.

Hessian for Newton Step

The full Newton variant uses ∇²h log p(y|h) to scale the Stein operator. For Student-t, the Hessian is straightforward. For OCSN, the mixture responsibilities rn and rc themselves depend on h, adding cross-terms. However, the expected Fisher information provides a stable scalar approximation:

// Fisher information (scalar, stable, never negative) Student-t: I(h) = (ν+1)/(2(ν+3)) OCSN: I(h) ≈ (1-α)·½ + α·1/(2κ²) // Full observed Hessian (more accurate, can be negative) OCSN: ∇²_h = -(½)·[r_n·z² + r_c·z²/κ²] + (¼)·[r_n·z² + r_c·z²/κ²]² - (¼)·[r_n·z⁴ + r_c·z⁴/κ⁴] + cross terms from ∂r/∂h
Core Engine

Newton–Stein Transport

This is where the posterior is computed. Everything else in the pipeline exists to make this step efficient. Newton-Stein is a deterministic transport operator that moves particles from the proposal distribution to the target posterior using the score function of the observation model.

The Stein Operator

// For each particle i, the Stein update direction is: φ(h_i) = 1/N Σ_j [ k(h_j, h_i) · ∇_h log p(y | h_j) ← attraction to high-likelihood regions + ∇_{h_j} k(h_j, h_i) ] ← repulsion from other particles // Newton variant: scale by inverse Hessian φ_newton(h_i) = H⁻¹(h_i) · φ(h_i) // Full Newton variant: Hessian inside the operator φ_full(h_i) = 1/N Σ_j [ k(h_j, h_i) · H⁻¹(h_j) · ∇_h log p(y | h_j) + ∇_{h_j} [ k(h_j, h_i) · H⁻¹(h_j) ] ]

The O(N²) kernel matrix k(h_i, h_j) computes pairwise interactions between all particles. Each particle feels two forces: the likelihood gradient pulls it toward regions where the observation is probable (attraction), and the kernel gradient pushes it away from other particles (repulsion). The balance between these forces shapes the posterior distribution.

The Hessian scaling is critical. Without it (standard SVGD), the step size must be conservative because the curvature of the log-posterior varies across the particle cloud. With Newton scaling, each particle's step is adapted to the local curvature — large steps in flat regions, small steps near the mode. This is the difference between first-order and second-order optimization, applied to distributional transport.

Why Full Newton

Standard Newton applies H⁻¹ after computing the Stein operator — it rescales the direction. Full Newton applies H⁻¹ inside the operator — it changes the kernel geometry. The Stein operator with Full Newton defines a Riemannian metric on the particle space where distances are measured in units of posterior curvature. Particles don't just move toward the posterior — they move along the natural gradient of the KL divergence between the current particle distribution and the target.

RMSProp Momentum

Each particle maintains a running velocity estimate via RMSProp. This smooths the transport across Stein iterations and across timesteps — particles that have been consistently moving in one direction continue to do so with less oscillation. The momentum term acts as a low-pass filter on the gradient signal, reducing the number of iterations needed for convergence.

// Per-particle velocity accumulator (persistent across timesteps) v_i ← ρ · v_i + (1-ρ) · φ(h_i)² h_i ← h_i + ε · φ(h_i) / (√v_i + eps)

KSD: Convergence Diagnostic

Kernel Stein Discrepancy is computed in the same O(N²) pass as the Stein transport — zero extra cost. It measures how far the current particle distribution is from the target posterior. KSD drives adaptive step budgets: high KSD means particles haven't converged, allocate more Stein steps. Low KSD means the posterior is well-approximated, stop early.

// KSD computed alongside Stein operator (free) KSD² = 1/N² Σ_{i,j} [ ∇log p(h_i)·k(h_i,h_j)·∇log p(h_j) + ∇log p(h_i)·∇_{h_j}k(h_i,h_j) + ∇_{h_i}k(h_i,h_j)·∇log p(h_j) + ∇_{h_i}∇_{h_j}k(h_i,h_j) ]
Transition Gradient

O(N²) Mixture Prior

The observation score ∇h log p(y|h) is only half the gradient. The full posterior score also includes the prior gradient — how likely is this particle's position given the previous timestep's particle cloud? Getting this gradient right turned out to be one of the largest accuracy improvements in the system.

The Problem

SVPF does not resample. After Newton-Stein transport, particle i at time t has no special relationship to particle i at time t-1. The particles have been deterministically transported to new positions. Yet the original implementation computed the prior gradient per-particle — each particle only looked at "its own" previous position. This is mathematically incorrect.

Per-Particle vs Mixture Prior

The correct prior is a Gaussian mixture over ALL previous particles. The probability that particle h at time t arose from the previous cloud is not determined by any single ancestor — it's the sum over all possible origins:

// The prior is a mixture over all N previous particles: p(h_{t} | Z_{t-1}) = (1/N) · Σ_j N(h; μ_j, σ²_z) where μ_j = μ + ρ · (h_prev_j - μ) ← AR(1) mean from particle j

Per-Particle Prior (Wrong)

// Each particle only looks at itself mean_i = μ + ρ · (h_prev[i] - μ) grad[i] = -(h[i] - mean_i) / σ²
Complexity: O(N). Each particle computes its gradient from a single previous position — the one that happens to share its index.
Wrong because: After Stein transport, particle i may have been moved far from particle i's previous position. The per-particle gradient pulls it back toward a position that has no probabilistic justification. This fights the Newton-Stein correction.

Mixture Prior (Correct)

// Sum over ALL previous particles float grad = 0.0f; for (int j = 0; j < n; j++) { float mean_j = mu + rho * (h_prev[j] - mu); float r_j = responsibility(h[i], mean_j); grad += r_j * (-(h[i] - mean_j) / sigma_sq); }
Complexity: O(N²). Each particle's gradient is a responsibility-weighted sum over all previous particles. Each ancestor contributes proportionally to how likely it is to have generated the current position.
Correct because: This is the exact gradient of the Gaussian mixture log-density. It respects the fact that SVPF transports particles without resampling — any current particle could have originated from any previous particle.

Responsibility Weights

The key mathematical object is the responsibility weight — the posterior probability that previous particle j "generated" current particle i:

r_j(h_i) = N(h_i; μ_j, σ²) / Σ_k N(h_i; μ_k, σ²) // "How likely is it that particle j at t-1 generated particle i at t?" // When h_i is near μ_j: r_j → large (strong contribution) // When h_i is far from all μ_k: r_k → uniform (uncertain origin) // When h_i is near one specific μ_j: r_j → 1 (clear ancestor)

This is structurally identical to the OCSN responsibility weights rn and rc at the observation level. Both replace a hard binary assignment with a soft probabilistic weighting. Same mathematics, same philosophy: don't make binary decisions, compute the mixture.

Why the Accuracy Boost

Under the per-particle prior, a particle that Newton-Stein correctly transported to a new region receives a strong gradient pulling it back toward "its" AR(1) prediction. The prior fights the likelihood. Under the mixture prior, if the particle is near any previous particle's prediction, the transition gradient supports its current position. The prior cooperates with the likelihood.

The effect is amplified during annealing. At early stages (β < 1), the likelihood is down-weighted but the prior gradient is at full strength. With the per-particle prior, early annealing stages are dominated by an incorrect prior pulling particles back to individual predictions. With the mixture prior, early stages have a correct prior that's already aware of the full cloud's support — particles can spread into the right region before the likelihood is fully turned on.

With Student-t state innovations, the effect compounds further. Heavy-tailed draws place tail particles far from the AR(1) mean. Under per-particle prior, those tail particles get a strong restoring gradient. Under mixture prior, if several particles landed in the tail (antithetic pairs guarantee symmetric coverage), they support each other through the responsibility weights. The tail is recognized as a legitimate region of the prior, not an accident to be corrected.

Computational Cost

O(N²) is Already the Price You're Paying

The Stein kernel matrix k(hi, hj) is already O(N²). The mixture prior gradient adds a second O(N²) pass with the same particle-pair loop structure. In practice, the responsibility weights can be computed in the same fused kernel as the Stein transport — one O(N²) pass computes both the mixture prior gradient and the kernel interactions. The correct computation is essentially free in asymptotic terms. O(N) but wrong, or O(N²) but correct — and O(N²) is already the cost floor.

Same Philosophy, Applied to the Prior

The per-particle prior was a hidden heuristic — an implicit assumption that each particle has a single ancestor, inherited from the resampling paradigm of standard particle filters. The mixture prior replaces that assumption with computation: evaluate the exact mixture density, compute the exact gradient, let Newton-Stein do the rest. No binary decisions, no index-based ancestry, no approximations. Computation solves the problem.

Temperature Schedule

Adaptive Annealing

When the observation is surprising — a 5σ return during quiet markets — the posterior is far from the prior. Jumping directly to the full posterior (β=1) would require particles to traverse a large distance in parameter space in a single step. The Stein operator is local — it computes gradients at current particle positions. If particles are far from the target, the gradients may be weak, misleading, or cause instability.

Annealing solves this by introducing the likelihood gradually. Instead of the full posterior, the Stein operator targets a sequence of tempered distributions:

π_β(h) ∝ p(h | h_{t-1}) · p(y | h)^β β = 0: pure prior (particles as predicted) β = 0.3: 30% likelihood influence β = 1: full posterior // Each β stage: run Stein steps against tempered target // Score at temperature β: ∇_h log π_β = ∇_h log p(h|h_{t-1}) + β · ∇_h log p(y|h)

KL-Constrained Beta Stepping

The adaptive annealing schedule is computed in a single GPU sync at β=0. The fused gradient-stats kernel evaluates the variance of log-likelihoods across particles. High variance means particles disagree about the observation's probability — the posterior is far from the prior, so beta must increase slowly. Low variance means the posterior is close to the prior, so large beta jumps are safe.

// At β=0, compute stats in single fused kernel: var_ll = Var_particles[ log p(y | h_i) ] // KL-constrained step size: Δβ = √(2 · KL_threshold / var_ll) // Additional constraints: Δβ_grad = 2 / mean|∇log p| ← don't overshoot based on gradient magnitude Δβ_space = f(h_std) ← tighter steps when particles are concentrated Δβ_final = min(Δβ, Δβ_grad, Δβ_space) n_stages = ceil(1 / Δβ_final) // Then fire all stages WITHOUT any more D2H syncs
Single-Sync Design

The entire annealing schedule is determined from one D2H transfer at β=0. All subsequent stages run asynchronously on the GPU. This means the CPU is free during the ~330 μs of Stein computation. The single sync costs ~5 μs; multiple syncs would cost 5 μs × n_stages — unacceptable for a system that measures total latency in hundreds of microseconds.

Why Not Fixed Schedule

A fixed schedule (β = 0.3, 0.65, 1.0) wastes computation when the posterior is close to the prior (most ticks) and under-allocates when the posterior is far (surprise events). The adaptive schedule automatically uses 2 stages during quiet markets and 15+ stages during crashes. Computation is allocated where it's needed.

EKF Guide

The Extended Kalman Filter guide is a linearized Bayesian update that runs before the Stein loop. It computes an analytical approximation of where the posterior should be, then softly shifts the particle cloud in that direction. The key word is softly — the guide doesn't collapse particles to a point, it translates the cloud while preserving its shape.

Preserving vs Non-Preserving

Non-Preserving Guide

h_i ← (1-α)·h_i + α·μ_guide
Direct interpolation toward guide mean. Shrinks particle spread by factor (1-α). After guide, particles are more concentrated — less diversity for Stein to work with.

Preserving Guide

cloud_mean = mean(h_i) shift = α · (μ_guide - cloud_mean) h_i ← h_i + shift
Translates the entire cloud toward the guide mean without changing the spread. Every particle moves by the same amount. The cloud's shape — its variance, skewness, tail particles — is perfectly preserved.
Chosen because: The Stein operator needs diversity to represent the posterior. Collapsing particles before Stein runs defeats the purpose. The guide's job is directional correction, not posterior approximation. Preserving the shape gives Newton-Stein the best starting material.

The Two-Tier Architecture

The EKF guide produces a vol estimate in ~2 μs as a side effect of computing the guide parameters. This estimate is available immediately — before the Stein loop even starts. For latency-critical decisions (order routing, kill switch), the guide estimate is sufficient. For accuracy-critical decisions (position sizing, risk), the full Stein posterior arrives ~350 μs later.

Why the Guide is Not a Heuristic

The EKF computes a first-order Taylor expansion of the same log-likelihood that Newton-Stein evaluates exactly. It's not a separate model or an external opinion — it's a cheap approximation of the same target. The guide and the Stein loop agree on what the answer should be; they differ only in accuracy. This is why the guide never fights the correction — it's a rough draft of the same computation.

Exploration

Stein Variational Langevin Dynamics

SVLD injects calibrated noise into the Stein transport step. Without noise, the Stein operator is deterministic — particles follow the gradient field exactly. Deterministic transport can get stuck in local modes or fail to explore regions of the posterior that are separated by low-probability valleys.

// Standard Stein step (deterministic): h_i ← h_i + ε · φ(h_i) // SVLD step (stochastic): h_i ← h_i + ε · φ(h_i) + √(2ε · temperature) · η_i η_i ~ N(0, 1) // Noise scale is proportional to: // √ε — vanishes as step size decreases // √temp — scales with annealing temperature // β_factor — vanishes as β → 1 (final posterior)

Ergodicity Guarantee

The SVLD noise guarantees that given enough iterations, particles will explore the entire support of the posterior. Without noise, if all particles start on one side of a bimodal posterior, they'll stay there forever — the deterministic Stein operator has no mechanism to jump across a low-probability valley. SVLD provides this mechanism.

In practice, the noise is most active during early annealing stages (low β, high temperature) when the tempered target is broad and exploration is cheap. As β → 1 and the target sharpens, the noise scales down and the transport becomes increasingly deterministic. The final Stein steps are nearly pure Newton transport — precise positioning with minimal perturbation.

SVLD + Annealing Interaction

Early stages (low β): broad target, strong noise → exploration. Late stages (β ≈ 1): sharp target, weak noise → exploitation. The annealing schedule naturally implements the explore-then-exploit strategy without any explicit switch. Temperature is the control variable for both the target sharpness and the noise magnitude — they're coupled by construction.

Why Not Other Exploration Mechanisms

SVLD ✓

  • Noise magnitude derived from theory (Langevin diffusion)
  • Couples naturally to annealing temperature
  • Fused into Stein kernel — zero extra compute
  • Vanishes at convergence — doesn't perturb final posterior
  • One parameter (temperature) with clear interpretation

MIM Jumps ✗

  • Jump probability is heuristic — no theoretical guidance
  • Jump scale is heuristic — wrong scale wastes particles
  • Binary decision: jump or don't — no gradual exploration
  • Active at all times — perturbs even converged posteriors
  • Three parameters, all requiring calibration

No Circular Dependencies

Information flows in one direction within a timestep: predict → guide → Stein → output. The only feedback loop is between timesteps: the posterior at t informs the prior at t+1 through adaptive μ. This means each component can be understood, tested, and debugged in isolation. There are no coupled nonlinear interactions that create emergent behavior. The system is compositional — the whole is exactly the sum of its parts.

Design Choices

Recurring Patterns

Principle 1: Computation Over Heuristics

Every tunable parameter is a liability. It encodes an assumption about market behavior that may be wrong tomorrow. The design minimizes parameters not out of elegance but out of robustness — fewer assumptions means fewer failure modes.

Where a problem can be solved by more computation (more Stein steps, finer annealing) or by a cleverer heuristic (jump detection, regime switching), always choose computation. Hardware improves every year — a 350 μs filter today is a 50 μs filter on next-gen GPUs without changing a line of code. Heuristics stay wrong at the same rate regardless of hardware.

Principle 2: The Gradient is the Only Information Channel

The observation score ∇h log p(y|h) is the only information channel from data to posterior. Every component either computes this gradient (Stein), approximates this gradient (EKF guide), or helps this gradient work effectively (annealing, SVLD, predict). Nothing in the system overrides or filters the gradient signal.

This is why the observation model matters more than the state model. A biased gradient propagates through every Stein iteration, every annealing stage. There is no downstream correction. Student-t's lik_offset is a band-aid for a biased gradient. OCSN eliminates the bias at the source.

Principle 3: Honest Uncertainty

The predict step should express genuine uncertainty, not confident guesses. Student-t innovations say "large moves are possible" without saying "this is a jump." Antithetic pairs say "the spread is exactly this wide" without saying "the mean is here." The guide says "the posterior is roughly here" without collapsing the spread.

Confidence should increase monotonically through the pipeline: the predict is maximally uncertain, the guide adds partial information, and Newton-Stein converges to the full posterior. No component should be more confident than the components that follow it.

Principle 4: Structural Motivation Over Calibration

Every modeling choice should have a structural justification — a reason derived from the nature of the problem, not from backtesting. The Student-t state model is motivated by the empirical fact that vol innovations are leptokurtic. OCSN observation noise is motivated by the physical reality that some ticks are microstructure garbage. Adaptive μ is motivated by the nonstationarity of long-run vol levels.

Contrast with heuristic choices: MIM jump probability calibrated to historical data, asymmetric ρ fit by grid search, lik_offset tuned to minimize bias on a specific dataset. These work until the market changes. Structural choices work because the structure of the problem doesn't change — returns will always have microstructure contamination, vol innovations will always be heavy-tailed, long-run vol will always drift.

Principle 5: Compositionality

Each component has one job. The predict step spreads particles. The guide shifts them directionally. Newton-Stein transports them to the posterior. SVLD prevents entrapment. Annealing controls the difficulty schedule. Adaptive μ tracks the long-run mean.

No component tries to do another's job. The guide doesn't try to be accurate — that's Stein's job. The predict doesn't try to be directional — that's the guide's job. SVLD doesn't try to find the posterior — that's Newton-Stein's job. This separation means you can modify, replace, or remove any component without understanding the others.

Summary

The goal is a filter where each component does one obvious thing for one obvious reason. No clever tricks, no surprising interactions. When the filter gives a wrong answer, the error should trace to exactly one component and be fixable without touching anything else.
